# 16 · Claude Code 三层验证闭环 × Poteto 五层倒金字塔门禁工程包（供 Coding Agent 直接挂载）

> **核心理念**：把 70% 的预算投在「不可被待审代码篡改的自动化验证闭环」，用架构防呆与静态 Lint 规则取代臃肿的万字 `AGENTS.md`。可直接把本文件丢给你的 Claude Code / Codex / Cursor，让它为你的仓库落地同款门禁。

## 一、Poteto 五层倒金字塔排障自检单（每次修完 Agent Bug 必跑）

每当修复一处由 Agent 引入的缺陷时，**严禁默认往 `AGENTS.md` 追加散文叮嘱**，按顺序回答以下 4 问并优先落在最高层：

| 优先级 | 免疫层级 | 灵魂拷问 | 落地形式示例 |
| :---: | :--- | :--- | :--- |
| **L1** | **架构与目录防呆** | 能否修改类型签名或物理目录隔离，让这类错误根本无法通过编译？ | 物理隔离主进程与渲染进程目录禁止互引；将裸密码存储替换为唯一无明文令牌封装 |
| **L2** | **0.1s 静态 Lint 门禁** | 能否写成 AST / 正则静态检查测试，在本地提交前 0.1 秒红灯拦截？ | 禁止业务层裸调高危 Hook；双向 i18n 键集合全等断言；禁止本机绝对路径残留 |
| **L3** | **端到端真机 `verify` 冒烟** | 能否通过浏览器 CDP / 模拟器 / 本地 API 真机跑一遍用户路径并留存截图？ | `.agents/skills/verify` 拉起真实服务校验 HTTP 200、像素裁切与状态落库 |
| **L4** | **按 Diff 触发的核对单** | 是否在 `>=2` 个 PR 重复出现且可由 Diff 路径精准触发？ | 写入 `REVIEW.md` 触发器表（只查本次 Diff 命中的 3～10 项） |
| **L5** | **人工终审介入** | 门禁连续失败满 3 轮仍未收敛？ | 立即停机呼叫人类工程师决断（严禁加 `sleep` 掩盖偶发失败测试） |

## 二、三层高信噪比验证模板（破除「写代码与写单测同源盲区」）

1. **端到端功能地图冒烟（E2E + Feature Map）**
   - 维护一份面向真实用户路径的 `FEATURE_MAP.md`（入口 URL -> 关键交互选择器 -> 预期落库状态与视觉断言），由独立 `verify` 脚本启动真实进程验证。
2. **属性不变量随机轰炸（Property-Based Testing）**
   - Python 使用 `hypothesis`、TypeScript 使用 `fast-check`、Web/终端 UI 使用 [`antithesishq/bombadil`](https://github.com/antithesishq/bombadil)，针对四大核心不变量生成千组随机输入：
     - **往返恒等（Round-trip）**：`decode(encode(x)) == x`
     - **业务红线不变量（Invariant）**：账本余额永不为负、索引条目更新后合法且不意外清零
     - **幂等性（Idempotency）**：迁移/同步/重试函数连续执行两次与执行一次状态完全一致
     - **等价性（Equivalence）**：优化后快路径输出严格等于朴素参考实现
3. **旧系统作裁判的差分回归（Differential Testing）**
   - 拆分大文件或重写核心管线时，回放真实请求样本同时通过旧实现与新实现，自动归一化时间戳与空白符后比对输出全等。

3. 检查现有测试中是否存在靠硬编码 sleep 糊弄的偶发闪烁测试（Flaky Tests），列出根因修复方案。
